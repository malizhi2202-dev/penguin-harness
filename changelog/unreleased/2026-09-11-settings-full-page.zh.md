# 系统设置：从弹窗改为整页

- **Date:** 2026-09-11
- **Type:** feat
- **Scope:** `web`

[English](2026-09-11-settings-full-page.md)

系统设置现在是 `/settings` 上的一个页面，每个分区有自己的 URL，不再是叠在当前页面上的弹窗。入口不变——侧边栏用户菜单的「系统设置」一行——只是从打开弹窗改为导航过去。

## 细节

- **每个分区都有地址。** `/settings/general`、`/settings/appearance`、`/settings/proxy` 等等；`/settings` 本身落在当前用户第一个可见的分区（个人组在前，非管理员永远不会被管理员的 URL 弹回来）。分区可以收藏、分享，浏览器回退键在分区之间往返，深链接直达它点名的分区。地址里出现当前用户无权查看的分区时，落到该用户自己的第一个分区，而不是把管理员表单渲染出来。
- **导航不变，空间更足。** 页面沿用弹窗的结构——个人 / 服务器分组、同一套分区、同样的管理员可见性规则——只是从 70vh 弹窗里的导航，变成内容区左侧的一列。全局配置分组下的三个库页面（插件库 / 模型库 / 智能体）渲染的就是 Project 在用的那三个整页，嵌入式打开，但享有整页的宽度与滚动；较浅的分区保持较窄的阅读列。
- **公共配置分区自成一个作用域，不牵动应用。** 三个库页面在一个钉死到公共配置的 Provider 下渲染：它们读的就是那份公共数据，而应用自身的作用域始终是某个 Project——侧栏、项目切换器、会话列表在访问这些分区的全过程中一动不动，离开时也没有需要「放回去」的东西。从模板卡片点开的编辑器有自己的路由（`/settings/commonAgents/:agentId`），作用域随 URL 走，因此它读到的是那个模板，而不是同 id 的 Project Agent。
- **移除**：设置弹窗及其分页容器。它们渲染的一切都在页面上；Modal 只留下真正的弹窗还需要的部分。

## 已知边界

- 从应用首次加载用浏览器回退退到 `/settings` 时，可能要等分区列表解析完才落到地址点名的分区；地址栏会被就地规范化，历史里不会留下中间 URL。
- 模板编辑页是设置分区之外的一条独立路由（它不显示设置页的左栏），这与从它返回的路径一致：返回键与页内返回都回到「智能体」分区。
