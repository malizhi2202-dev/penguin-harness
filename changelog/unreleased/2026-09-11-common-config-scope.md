# One common configuration scope for models, Agent templates and default plugins

- **Date:** 2026-09-11
- **Type:** feat
- **Scope:** `core`, `server`, `web`, `docs`

[中文版](2026-09-11-common-config-scope.zh.md)

A data root now carries an optional **common configuration scope** at `<root>/common/`, configured once and drawn on by every Project: its Model table, its Agent templates, and the plugin set a newly created Agent is seeded with. Each of the three comes across by its own rule — models and templates are *copied*, the default plugin set applies only when whoever creates an Agent selects nothing — and a Project is independent of the scope from the moment it has copied from it.

## Details

- **Models are copied.** A new Project is seeded with the whole common table at creation, credentials included, so it is usable the moment it appears (and a common scope with no models still starts from the built-in presets). Models added to the common side later are pulled into an existing Project with the models page's "Import from common config" (`POST /api/projects/:p/models/import-common`, owner). The import only appends: an entry the Project already carries under the same `(provider, model_id)` pair keeps its own credential and metadata, `default_model` and `vision_model` are adopted only where the Project had none, and `addedCount` reports what actually landed. A common scope with no models answers 409 `no_common_models` rather than an empty success.
- **The scope starts with the General Agent.** Its Agent list is provisioned on the first read with the same builtin `default_agent` a Project is created with (preinstalled library plugins included), so the scope opens on a template an administrator can edit in place rather than on an empty list, and a Project's create dialog can offer it immediately. The seeding runs only for the reserved id, only while the scope holds no Agent at all, and never overwrites an existing one — no Project's own General Agent is read or copied, and a data root nobody opens the scope in still gets no `common/` directory.
- **Agent templates are copied.** Creating an Agent with `templateAgentId` copies that template's behavior — `system_config.yaml`, `AGENTS.md`, `skills/`, `hooks/` and `tools/` — while `.vault.toml`, `memory/` and `schedule/` stay behind: credentials, that Agent's personal memory and its timed work are not behavior. A `name` / `description` in the same request wins; without one the new Agent keeps its own id. A template that no longer exists is a 404 `agent_not_found` raised before anything is created, so no half-made Agent is left behind.
- **The default plugin set applies when nothing was chosen.** `<root>/common/plugins.toml` holds `default_plugins`; those names are installed on a new Agent whose creator selected no plugins, no template and no snapshot. An explicit empty list means "none", so the picker can let a user clear the pre-selected defaults. Names are resolved against the built-in library before the file is written (400), and a name the library later drops is reported back as `unknownPlugins` instead of blocking the rest of the editor. An absent file means "no defaults", which is what creating a plain new Agent did before.
- **The scope is not a Project.** It reuses the reserved id `common` and a Project's own path layout, but it is never listed, never creatable, renamable or deletable, and no Session can start inside it. An admin resolves there as owner through the ordinary Project routes — which keeps every existing write route (Agent creation, config, skills, hooks) admin-only without a second rule — while for anyone else `/api/projects/common/…` answers the same 404 an inaccessible Project gives.
- **The CLI addresses it too.** The reserved id is an ordinary `--project-id` value, so `penguin config model … --project-id common` edits the common table directly on this machine's data root.
- **Two reads stay open to any signed-in user**, because they are what a member needs in order to create an Agent inside their own Project: `GET /api/common/plugins` (the default set) and `GET /api/common/agent-templates` (template identity plus skill and hook counts — no config body, Skill content or credential).
- **With no `common/` directory, nothing changes**: the built-in preset catalog, an empty default plugin set and an empty template list, exactly as before.
- **Web App**: administrators open the scope's three surfaces (Plugin Library, Models, Agents — the very Project pages, reading the common config instead) directly inside **System settings → Global config** (a group of its own below the server's). The settings page carries the scope for them, so the app's own scope never changes: the switcher lists Projects only and the sidebar keeps showing the current Project's nav throughout. Also here: an "Import from common config" action on the models page, a template picker and default-plugin pre-selection in the create-Agent dialog, and the "Default plugins for new Agents" editor in the plugin library. Chat and the per-Project statistics pages are not offered inside the scope, and Models, Agents and the library are what it is for.
- A data root that already carries a Project under the reserved id keeps that Project working — Sessions, rename and delete included — and simply has the scope unavailable until that Project leaves the id; the decision and its removal condition are recorded in [this batch's compatibility entry](2026-09-11-backward-compatibility.md).
