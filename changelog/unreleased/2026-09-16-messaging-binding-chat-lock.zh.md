# 消息绑定只服务第一个说话的会话，其他会话一律忽略

- **Date:** 2026-09-16
- **Type:** fix
- **Scope:** `server`, `docs`
- **Breaking:** yes — 已绑定的渠道过去会回复「最后说话」的那个会话，现在只服务第一个对它说话的会话，来自其他会话的消息一律忽略

[English](2026-09-16-messaging-binding-chat-lock.md)

一份绑定只记一个回复目标，并且谁最后说话就把它挪给谁，于是两个群同时 @ 机器人会共用同一条 Session 上下文，每条回复都落到最近说话的那个群里。现在会话只选定一次——第一个对这份绑定说话的会话——此后来自其他任何会话的消息都被忽略。

## 细节

- 记住的会话就是绑定行自己的 `lastChatId`，因此这条规则不需要新字段、不需要 API 字段、也不需要迁移，并且跨重启保留。
- 判定发生在到达时间戳之前、也在任何出站客户端建立之前：被忽略的消息只花一次行读取，不触碰这份绑定记住的其他任何东西。
- 静默忽略而不是回绝，因为从未被邀请的会话不该从一次拒绝里得知机器人存在。
- Telegram 的论坛话题各自算一个会话，因此绑定会锁定在第一个对它说话的话题上。

## 兼容性

- 无需迁移，数据不变。既有绑定继续在它的 `lastChatId` 已经指明的那个会话里工作——也就是它被创建时所在的会话，或它最近回复过的那个会话——因此一个已经漂移到别处的绑定会留在原地，直到被有意搬走。
- 想把绑定换到另一个会话，在网页端删除该渠道的配置再重新添加即可：下一条消息选定会话，此前那个会话从此被忽略。
