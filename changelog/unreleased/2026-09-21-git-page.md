# The Git page: a Project's local repositories, from the sidebar

- **Date:** 2026-09-21
- **Type:** feature
- **Scope:** `server`, `web`

[中文版](2026-09-21-git-page.zh.md)

The sidebar's nav group gains 代码仓库 (`/git`): the local git repositories under the current
Project's Workspaces, with their commit log, working-tree changes and branches, read straight from
the `.git` on the server's disk. Nothing talks to a hosting platform — this is the checkout the
Sessions in that Workspace are actually editing.

## Details

- Discovery is by Workspace. The candidates are the directories the Project's Sessions ran in
  (plus the sidebar's registered Workspaces and any directory picked on the page), and each is
  resolved to its repository top level, so several Workspaces inside one repository are one row
  and a directory that is not in a repository is skipped rather than reported as an error. The
  scan is capped and reports what it left out instead of truncating silently.
- The page reads: one repository's branch, upstream distance, status counts, branches and remotes;
  a paged commit log; one commit's message body, per-file line counts and patch; and one file's
  diff against the index, against the working tree, or as it was in a commit. Untracked files are
  diffed against `/dev/null`, so a new file has something to show before it is ever staged.
- The page writes: stage, unstage, commit (with an optional amend), switch to an existing branch,
  and fetch / pull / push. Committing takes only a message — staging is its own button, so a
  commit cannot quietly pick up files the reader did not choose — and the git output of every
  command is shown as git printed it.
- Every argument that reaches git is validated in the service: a revision is resolved to a SHA
  before it is used (so `--output=…` is not a revision), a pathspec that leaves the repository is
  refused, branch names are checked against `git for-each-ref`, and git runs with
  `GIT_TERMINAL_PROMPT=0` under per-command timeouts, so no route can hang on a credential prompt.
- Every route is Project-scoped on the existing access rule (an outsider gets 404, not 403) and
  lives under `/api/projects/:projectId/git/`.
