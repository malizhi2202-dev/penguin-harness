## id 为 `common` 的 Project 不会被公共配置作用域遮蔽

公共配置作用域占用了保留的 Project id `common`，自本次发布起，用该 id 创建 Project 会被拒绝。早于该作用域存在的数据根目录里仍可能带着这样一个 Project，而它的目录正是作用域读写的那个 `<root>/common/`。

**若什么都不做会坏在哪：** 保留 id 会赢。该 Project 的成员会失去访问权（404），其所有者无法在其中开会话（400），也无法改名或删除；而所有公共作用域界面会把该 Project 自己的文件当成作用域的来读写——包括把该 Project 的模型表与凭证复制给此后新建的每一个 Project。

**决定（用户的选择）：** 保护性回退，而不是迁移。只要存在占用该 id 的 Project，作用域就**停用**，而这个 Project 分毫未动：它按普通 Project 解析，所有者与成员照常访问，会话照常开启，改名与删除都与从前一样可用。每一个仅属于公共作用域的界面改答 409 `common_scope_conflict`——`/api/common` 的两个读接口与写接口、`import-common`，以及模板清单。与此同时新建的 Project 从内置预设起步，而不是从那个 Project 的表复制；新建 Agent 也不会套用默认插件集。Web App 不再提供公共配置切换入口，界面上不会指向一个注定拒绝的作用域。

**生效范围：** 数据根目录的目录布局，以及 `web.db` 的 `projects` 表里的一行。没有文件被重写，也没有任何东西被搬动或复制：回退只是决定同一个目录取两种含义中的哪一种。

**用户需要做的：** 升级时什么都不用做。只要那个 Project 还在，作用域就不可用。启用它只有两条路，且都不需要重启——这个判断是每次调用时做的，不是启动时做的：

- **删掉那个 Project**（就是它自己的删除操作，会连同它的目录一起删除）；或者
- **给它换一个 id**，适用于数据必须保留的情形：Project 的 id 同时是它的目录名、Workspace 路径与所有已存引用，因此在所有界面上一律设计为不可变，换 id 属于数据根目录层面的操作——停掉服务，执行 `UPDATE projects SET project_id = '…' WHERE project_id = 'common'`，把 `<root>/common` 目录改成同名，再启动。（在界面里改名只改显示名，所以并不能解除这次撞车。）

冲突提示里两条都写了，因为那是用户唯一能得到的指引。

**移除：** 相关代码是 `ProjectService.isCommonScopeBlocked` 及其各个调用点（`/api/common` 路由、`ProjectConfigService` 读取公共表与 `importCommonModels`、`AgentService` 的默认插件播种、`SessionService` 的保留 id 拒绝），以及 `app.ts` 里那条谓词的接线；每一处的注释都是同样的说法。当不再可能有数据根目录带着这样一个 Project 时就可以删除——既然创建时已拒绝该 id，剩下的纯粹是「为旧版本升上来的窗口留多久」，由维护者在准备发布时决定。删除是纯粹的删除：没有别处引用这个判断，也没有任何已存数据依赖它。

## 本批次其余部分无需处理

这个作用域在磁盘上与接口上都是纯增量的：`<root>/common/` 是新目录（缺省不存在，而不存在就意味着所有界面维持原有行为——内置模型预设、没有默认插件集、模板清单为空），`AgentCreateRequest.templateAgentId` 是已有路由上的可选字段，新增接口也不承载任何此前存过的形态。空的 `pluginNames` 现在明确表示「就是不要插件」，而此前省略也得到同样的结果——磁盘上没有任何数据编码过这一区别，因此没有任何已存请求会被重新解释。取值为保留作用域的 `lastProjectId` 与任何过期 id 一样解析：Project 列表查不到，用户落到自己第一个可访问的 Project。

在此记录只是为了说明已做过检查。
